## 3. Evaluation discipline (anti-overfitting)

- The five sets are the **control column only**. They are **not** a
  model-selection set.
- During short runs: log training diagnostics + periodic checkpoints; use cheap
  **offline/imagination** diagnostics for monitoring.
- Evaluate **the final or a predeclared checkpoint** on all five.
- If an intermediate checkpoint must be chosen, selection uses a **predeclared
  training/offline criterion** (held-out replay error), never the five-seed control.
- Report **all five per-seed values plus SD/range**, never the mean alone.

## 4. Verified loss fractions (§6) — my earlier denominator was wrong

I re-derived these from the implemented reduction
(`flow_matching.py:276-288`), not from an assumed weighted mean:

```
error  = |pred − target|                      (loss_type = "l1")
active_weights = weights * conditioning_mask
denominator    = conditioning_mask.sum()      # ELEMENT COUNT, not weight sum
loss = (error * active_weights).sum() / denominator
```

**Masking order:** weights are built once (`_make_loss_weights`), then multiplied
by the mask; the mask covers **only** the observation slice at t∈{0,4}
(`_make_conditioning_mask`, `flow_matching.py:217-221`). No normalization over
state dimensions is applied — `dim_weights = ones(483)`.

| quantity | value |
|---|--:|
| denominator (`mask.sum()`, element count) | **1455** |
| sum of active weights | 1482.0 (**not** the denominator — the reduction is not a weighted mean) |
| **(A) t=4 placeholder share of ACTION loss weight** | **7.14%** (3/42 = 1/14) ✔ |
| **(B) t=4 placeholder share of TOTAL weighted loss** | **0.2024%** |
| observation share of total | 97.17% |
| action share of total | 2.83% |

**(A) 7.14% is confirmed** and matches the `10+1+1+1+1 = 14 → 1/14` reasoning.
**(B) is 0.20%.** These must never be conflated: the placeholder is a large
fraction of the *action* signal and a tiny fraction of the *total* objective.
The case for N1 rests on (A).

**Correction to my Phase-0 wording:** I previously wrote "7.14% of the entire
action learning signal" against a denominator of 1482 (summed weights). The
correct implemented denominator is the element count 1455; the (A) figure is
unchanged because it is a ratio within the action block, but the total-loss
framing needed the separate (B) number.

## 6. Semantic loss formulation (§8, §9)

The code **already logs** independently masked means
(`flow_matching.py:293-296`): `action_loss = masked_mean(error[...,:3], action_mask)`
and `observation_loss = masked_mean(error[...,3:], observation_mask)`. These are
the semantically normalized per-element quantities we need — no dimension counting.

Proposed objective for the screening arms:

```
L = λ_state · L_state + λ_action · L_action
L_state  = masked_mean(error over observation slice)     # per-element
L_action = masked_mean(error over action slice)          # per-element
```

with the **first-action weight kept separate and unchanged** (§10).

**λ values will be chosen from a measured baseline, not guessed.** The current
effective ratio is not 1:1 — it is set implicitly by
`action_share/observation_share = 2.83/97.17` in weight terms, but the *loss
scales* differ too. **Before fixing C/D I will run a zero-GPU (or ≤0.05 GPU-h)
probe that logs baseline `action_loss` and `observation_loss` magnitudes on a few
hundred training batches**, then set λ_action so the weighted action contribution
is ~2× and ~5× its current effective share. Proposing numbers before that
measurement would be exactly the "choose weights to equalize scalars" error §8
forbids.

## 7. Separate state/action denoising schedules (§13) — design audit

Let global inference progress be `s ∈ [0,1]`, with `t_state = f_state(s)`,
`t_action = f_action(s)`.

| option | definition | inference-only? | retraining? | time embedding | mismatch introduced | conditioning implications |
|---|---|---|---|---|---|---|
| **BASELINE** | `f_state = f_action = s` | — | no | one global `t` | none | current mask unchanged |
| **STATE-FIRST** | state advances to clean earlier; action held at noisier `t` until `s₀`, then both advance | **yes, as a diagnostic** | not for the diagnostic; **yes** for a real model | one global `t` **cannot express this** — needs per-token `t` | **yes**: the net was trained with a single `t` for all tokens, so feeding tokens at different effective times is off-distribution | mask unchanged; action slice never conditioned, so freezing it is legal |
| **ACTION-DELAYED** | `f_action(s) = max(0, (s−s₀)/(1−s₀))`, `f_state(s)=s` | yes (diagnostic) | yes (real) | same as above | same | same |
| **SOFT OFFSET** | both monotone but warped, e.g. `f_action(s)=s^γ` | yes (diagnostic) | yes (real) | same | milder but still off-distribution | same |

**Architecture finding (from Phase 0):** `_time_embedding` takes `time` of shape
`[batch]` and adds it to **every** token
(`pint.py:190-191`, `x_proj = x_cat + t_embed[:,None,None,:]`), and
`AdaLNPINTDenoiser` **explicitly raises** on interval conditioning
(`pint.py:139-142`). So separate semantic times are **architecturally
unexpressible today**.

**The cheap test exists and is the right first move (§13's key question).**
Because the action is **token 0** with its own `action_projection`/`action_encoding`
and state particles are tokens 1..N (`pint.py:165-187`), a **token-type-conditioned
time embedding** (option B) is surgical: add `t_action` to slot 0 and `t_state` to
slots 1+. And crucially, an **inference-only schedule diagnostic requires no
retraining at all**: hold the action slice's update frozen for `s < s₀` while
letting state integrate, then release. That is a mismatched-but-informative probe
(§13 explicitly allows this as an intentional diagnostic) costing well under
0.5 GPU-h, and it tells us whether the direction has promise before we commit to
retraining with dual time embeddings.

**Do not implement before MeanFlow + loss screening**, per §7/§13.

### MeanFlow short-run design (§8) and stop gates

**Question it answers — only this:** *does MeanFlow train at all on the real
PandaPush formulation?* Not final performance.

Justification for the design: there is **no usable PandaPush MeanFlow checkpoint**
(best is 201 steps), and the OGBench record shows boundary iMF's *interval* loss
worsening at 5000 steps while the decisive 50k run was never executed. So the run
must be long enough to distinguish "learns" from "undertrained".

- **Arm:** `ImprovedMeanFlow` (boundary) on 3-cube PandaPush, **current
  formulation** — no N1, no λ change, `action_weight=10` retained.
- **LR:** start at **4e-5** (half), not the canonical 8e-5 — the OGBench stability
  screen recorded 8e-5 **diverging**. Predeclared, not tuned.
- **Staged checkpoints** at 1k / 2.5k / 5k / 10k / 20k steps, logging **LIVE and
  EMA separately** at every stage (prior auxiliary-iMF EMA/live gap was 55% → 4.8%).
- **Assert** in the run log that the boundary mask fraction is 0.5 per microbatch
  under `shuffle=True` + `gradient_accumulate_every=8`.

**Terminate early — do not consume the 6 hours if the answer arrives sooner — if
any of:**
1. training loss does not decrease by the 2.5k checkpoint;
2. any NaN/Inf in loss or grads;
3. action outputs collapse (near-constant, or >50% clipped — prior runs hit 79%);
4. imagination at NFE10/15 remains nonsensical at the 10k checkpoint;
5. LIVE and EMA diagnostics diverge badly (EMA failing while live improves);
6. projected cost from the timing probe would exceed 6 GPU-h.

**Gate:** if MeanFlow fails fundamentally → **diagnose, do not proceed to loss
screening**. If it trains and produces nondegenerate actions/states → Phase 3.

## 10. Imagination protocol (§11) and partial-denoising layout

**Reuses `experiments/scripts/dlp_imagination.py`** (already decodes DLP→RGB and
saves figures, with the 48 = 2×24 multiview split handled) rather than new code.

**A. Decoded trajectory grid.** Existing Standard Flow checkpoint (seed 42, step
499000, EMA). NFE ∈ {1, 2, 4, 10, 15, 32}. Same initial observation, same goal,
same latent noise across NFE where technically valid (identical `z` per example).
Rows = NFE, columns = predicted timesteps t=0..4 (with row 4 labelled **GOAL**,
not `t=4`, per the Phase-0 finding). 3–4 fixed examples chosen by a stated rule
(first N of the frozen set), not hand-picked.

**B. Partial-denoising progression.** For a fixed example and fixed NFE (32, so
intermediate states exist), decode the trajectory at integration progress
`s ∈ {0.0, 0.25, 0.5, 0.75, 1.0}`. Layout: **rows = physical prediction timestep
t=0..4, columns = denoising progress** — immediately readable left-to-right as
"noise → clean". Show cubes/entities and the goal. Action is 3-D; it is
represented as a small arrow/vector overlay on the eef, **not** as a decorative
latent plot.

Quantitative companion: **neutral-replay** metrics only (the frozen arm-neutral
protocol). **No policy-authored targets.**

**If NFE10/15 look visibly incoherent → flag before training another variant.**
